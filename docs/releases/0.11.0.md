# Marqov SDK 0.11.0

A minor release with two behaviour changes that make results and
configuration mean what they say: sparse qubit indices are kept in place
instead of being silently renumbered, and `MarqovDevice` and
`ExecutorFactory` read the same backend settings under the same names.

## Install

```sh
python -m pip install --upgrade "marqov==0.11.0"
```

Python remains >=3.12. Use Python 3.12 for `[all]`, `[rigetti]` and `[pyquil]`.
Dependencies are unchanged from 0.10.1, including the `qiskit<2.6` ceiling.

## Highlights

- **Sparse circuits keep their qubit positions.** `Circuit().x(2)` is three
  qubits wide and gives `{'001': N}` on `LocalExecutor`; before, it reported
  one qubit and `{'1': N}`, indistinguishable from `Circuit().x(0)`. Qubit
  `i` sits at register index `i` in every export, and qubit 0 is the leftmost
  character of a counts key. Braket and Rigetti are sent only the qubits a
  gate touches (no identity gates reach hardware), and their counts are
  widened so the keys still have the full width.
- **One set of backend parameter names.** `MarqovDevice` and
  `ExecutorFactory` accept the same canonical keys (`channel`, `instance`,
  `token`, `optimization_level`, `subscription_id`, `resource_group`,
  `workspace_name`, `location`). An IBM `optimization_level` passed to
  `MarqovDevice` is now honoured instead of silently ignored.
- `from marqov.executors import LocalExecutorConfig` works.
- `mypy marqov` passes under an enforced configuration.

## Upgrading

See the Upgrading section of `CHANGELOG.md` under 0.11.0. In short:

- For circuits on sparse indices, `num_qubits` and the length of every counts
  key grow to the largest index plus one. Circuits using qubits `0..n-1` are
  unchanged.
- The `ibm_*` and `azure_*` parameter spellings still work but warn; give
  both spellings different values and you get `ValueError`. With canonical
  keys only, an IBM `MarqovDevice` dict needs `channel` or `instance`
  alongside `token`.
- Identity-only circuits are refused before Braket or Rigetti submission, and
  a negative or non-integer qubit index raises `ValueError` as soon as the
  circuit is simulated, executed or exported.

See `CHANGELOG.md` for every entry with its pull request.
