# Marqov SDK 0.8.0

This minor release adds managed native workflow submission to the hosted
platform client. Existing behaviour of `submit()`, `Job`, `PlatformResult`,
workflow capture and executors is unchanged. Python remains >=3.12.

## Install

```sh
python -m pip install --upgrade "marqov==0.8.0"
```

Dependency declarations are unchanged from Marqov 0.7.1.

## New: run a saved `@task`/`@workflow` program on the hosted platform

- `MarqovClient.managed_runtimes(team_id)` lists the managed native runtimes
  enabled for a team.
- `MarqovClient.submit_native(...)` submits a saved script (`script_id`) or
  inline `source` and returns the ordinary `Job` handle.
  - `team_id` and `cap_cents` are required; the SDK never chooses a spending cap.
  - The request is validated before anything is sent.
  - The runtime must match discovery exactly; no other backend or runtime is
    substituted.
  - The `Idempotency-Key` (yours, or one generated per submission) is reused
    across retries.
  - If a failure happens after the request may have been sent, the error carries
    the key as `exc.idempotency_key`. Resubmitting with it reveals the outcome
    without admitting twice.
- A completed workflow's `result().raw` is the platform's
  `marqov.managed-result/v1` projection; each output's JSON value is in
  `display.value`.

See [Native workflows on the hosted platform](../platform-client/native-workflows.md)
for the complete discover → submit → wait → read example and the refusal codes.

## Behaviour to know

- The admission receipt is checked for structure and input hash, and for source
  hash when the source is known locally (inline `source`, or `source_sha256` for
  a saved script). For a `script_id` without `source_sha256`, the client cannot
  independently verify which source content the platform ran.
- The documentation now states what the hosted API does not currently accept:
  - `submit()` for native `@task`/`@workflow` or plain Python, and inline code to
    paid backends;
  - `Circuit` submission;
  - `job.cancel()` with an API key;
  - `platform_info()`.

  These calls are unchanged in this release.
- Your program runs on the platform's pinned SDK version; the locally installed
  version affects only the client calls.

## Qualification

The implementation passed the SDK's local suite (Python 3.12 with all backend
extras) in CI, including contract tests whose golden request bodies are also
accepted by the hosted API's request handler.

Before release, this exact code was installed from Git and ran against Marqov's
authenticated staging environment. The run:
- discovered the runtime;
- submitted a saved native workflow through `submit_native`;
- read the expected result;
- confirmed that a same-key replay returned the same job;
- confirmed that another team's key was refused.

Cleanup of the test window was verified separately.

This release does not change platform runtime pins or publish runtime images.
Platform adoption of 0.8.0 is a separate deployment decision.

Publication status and the release tag are recorded on the
[GitHub release page](https://github.com/marqov-dev/marqov-sdk/releases/tag/v0.8.0).
