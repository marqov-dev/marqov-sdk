# Marqov SDK 0.12.0

A minor release. Circuits keep the width they were declared with, both Azure
Quantum paths work again, the platform client gains `marqov watch`, and the
getting-started docs match what the hosted platform accepts.

## Install

```sh
python -m pip install --upgrade "marqov==0.12.0"
```

Python remains >=3.12. Use Python 3.12 for `[all]`, `[rigetti]` and `[pyquil]`.
`pip install marqov` no longer installs `azure-quantum`; Azure users install
`marqov[azure]`. The `qiskit<2.6` ceiling is unchanged.

## Highlights

- **Circuits keep their declared width.** `Circuit(num_qubits=n)` declares a
  width, and `from_qiskit()` and `from_openqasm()` keep a register's unused
  qubits: `qreg q[6];` with gates on `q[0]` and `q[3]` is 6 qubits wide (it
  was 4). A qubit that only a measurement touches counts toward the width on
  Braket, Cirq and pyQuil imports.
- **Azure Quantum works through both paths.** `AzureQuantumExecutor` no
  longer sends a barrier, which Rigetti targets refused, and `MarqovDevice`
  can run on Azure at all (no run could succeed before). Both submit the same
  program through `AzureQuantumProvider(...).get_backend(target).run(...)`
  and return the same counts, qubit 0 leftmost. Checked with live jobs on
  `rigetti.sim.qvm` through both paths; `quantinuum.sim.h2-1sc` accepted the
  program. IonQ targets on Azure were not run.
- **`marqov watch`**, a read-only terminal view of your Marqov Platform jobs,
  with `MarqovClient.recent_jobs()`, `projects()` and `project_jobs()`.
- **Three-qubit gates:** `Circuit.ccx()` and `Circuit.cswap()`, with
  `toffoli()` and `fredkin()` aliases, imported from Qiskit, Cirq, PennyLane
  and pyQuil.
- **Platform client docs match the hosted API.** Examples submit a `Circuit`
  or an OpenQASM string to `backend="local"`. Submitting a `Circuit` needs
  `pip install "marqov[openqasm]"`; an OpenQASM string needs no extra.
  Cancelling with an API key is refused by the platform; cancel from the job
  page.
- **Self-run Temporal workers:** task results and arguments are capped at
  Temporal's 2 MB payload limit with an error that names the task, and a
  workflow sends each task only its own dependencies' results. The hosted
  platform does not run this engine and is not affected.

## Upgrading

See the Upgrading section of `CHANGELOG.md` under 0.12.0. In short:

- Counts keys for a Qiskit or OpenQASM import with unused qubits at the end
  of a register grow to the declared width. Circuits whose gates reach the
  last declared qubit are unchanged.
- Azure users install `marqov[azure]` or `marqov[all]`.
- If you run the SDK's Temporal worker yourself, drain running workflows
  before upgrading it, and keep task results and arguments under 2 MB.
- Keep both sides of a Circuit pickle boundary on the same `marqov` version.

See `CHANGELOG.md` for every entry with its pull request.
