# Marqov SDK 0.10.0

A correctness release. A review of the changes between 0.8.1 and 0.9.1 found
twenty-one defects, and a second pass closed nine more open issues in the same
vein. Remote executors now keep the provider job identity on every exit after
submission, provenance records report observed rather than requested values,
options and settings an executor cannot apply fail loudly instead of being
ignored, and workflow task arguments travel intact. It also caps `qiskit`
below 2.6 to work around an upstream break on Linux.

## Install

```sh
python -m pip install --upgrade "marqov==0.10.0"
```

Python remains >=3.12. Use Python 3.12 for `[all]`, `[rigetti]` and `[pyquil]`:
those optional dependency combinations are not qualified on Python 3.13.
Do not install upstream `quantumflow` alongside `marqov-quantumflow`; both
provide the same import package.

## Highlights

- Braket, IonQ (legacy route), IBM, SpeQtrum and Quantum Brilliance remote
  attach the provider job identity (`remote_job` plus a note) to every error
  raised after a job is submitted, including caller cancellation, so a job is
  never lost or double-submitted. Interrupted waits log the job id, which
  survives `asyncio.run()` turning a cancellation into `KeyboardInterrupt`.
- `IBMExecutor` releases the caller at `timeout_seconds` instead of blocking
  `asyncio.run()` until the queued job finishes.
- Every entry point refuses options it does not apply, with a `TypeError`
  naming the option, so a typo or an unimplemented option can no longer run as
  if it had been applied. Dead IBM config fields are rejected the same way.
- Azure Qiskit results carry the provider's cost and execution time; Azure
  status no longer reads `Unavailable` as available; QiliSDK and CUDA-Q refuse
  results whose shot totals differ from the request; Qristal records the noise
  model.
- `Circuit.to_openqasm()` and `to_qiskit()` are deterministic (register `q`),
  so program hashes are stable; QASM 2 `swap` round-trips; `from_braket`
  accepts terminal measurements; `to_pyquil` exports Braket-imported gates.
- Workflow task arguments and results that are not JSON (a `Circuit`, an
  array, a dataclass, a dict with non-string keys) arrive as the original
  objects; oversized or unresolvable inputs fail at dispatch.
- Alice & Bob and CUNQA are routable through `ExecutorFactory`; NumPy integer
  shot counts are accepted everywhere; `preflight()` no longer reports a dry
  run it never attempted.

## Upgrading

See the Upgrading section of `CHANGELOG.md` under 0.10.0 for the full list.
The ones most likely to need a code change:

- Any option an executor or `MarqovDevice.run()` does not apply now raises
  `TypeError`; remove it or move it to the config field that implements it.
- `IBMExecutorConfig` with `resilience_level` other than 1 or
  `poll_interval_seconds` other than 2.0 raises at construction; edit stored
  backend configs that carry other values.
- IBM: a result the SDK refuses after retrieval raises `ValueError` or
  `NotImplementedError` naming the job, not `IBMExecutionError`.
- `AzureQuantumExecutor.is_device_available()` is False for `Unavailable`;
  `get_status()` reports `maintenance` for anything it cannot read.
- `PreflightResult.dry_run_passed` is `None` by default; test `is True`.
- Workflow task bodies written against JSON-coerced arguments (string keys,
  ISO date strings, dicts for dataclasses) now receive the original objects;
  `run()` returns decoded objects, not the cloudpickle envelope.
- Dependencies: `qiskit<2.6` in every extra (qiskit 2.6.0 exhausts static
  thread-local storage on Linux and breaks pennylane-lightning's binary
  import); `qiskit-ibm-runtime>=0.21.0` in `[ibm]` and `[all]`.
- Exports: the Qiskit register is always named `q`.

See `CHANGELOG.md` for every entry with its pull request.
